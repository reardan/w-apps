A browser built from W

The first useful step is a document that you can read. A window is only the beginning: text needs a layout, links need destinations, and navigation needs to preserve a page while the next one loads.

From source to a page

W parses the source into a tree. Win walks that tree and builds lines of text. Each word has a font, a position, and a width. When a word no longer fits, the line ends and a new one starts.

Text can be bold, italic, or a link. These inline elements stay in the paragraph instead of turning into separate UI widgets.

Navigation is state

Following a link records the old location. Back and Forward visit that history and restore the scroll position. A fragment link names a position inside the current document.

  • A slow request runs in a separate loader process.
  • Stop closes that loader and leaves the current page readable.
  • Starting another navigation discards the previous request.

Small, explicit boundaries

Documents are limited to one mebibyte. The parser also limits tree depth and node count. Unsupported document types produce a visible loading error. Network certificates are verified by W's TLS stack.

Text and language

UTF-8 examples: café, naïve, Ελληνικά, Кириллица. The bundled fonts cover these scripts; shaping and wider font fallback remain separate work.
